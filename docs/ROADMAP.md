# План развития ModelBoard

**Текущий приоритет: этап 1 — Canvas.**

ModelBoard задуман как единое рабочее пространство, сочетающее визуальную доску, табличный редактор и связанную модель данных. Мы строим эти части **по очереди**, чтобы получить законченные пользовательские сценарии, а не коллекцию несвязанных MVP-функций.

Четыре этапа:

1. **Canvas:** удобство и надёжность уровня современных whiteboard-редакторов (ориентиры по UX: FigJam, Miro, Figma; не попытка воспроизвести все функции Figma).
2. **Spreadsheet:** удобное редактирование встроенных и полноэкранных таблиц, знакомое пользователям Excel.
3. **Объекты и связи:** семантические отношения, взаимосвязанные схемы и реиспользуемые представления одних данных.
4. **Файлы и экосистема:** drag-and-drop, импорт/экспорт, SVG/медиа, библиотеки и интеграции.

> Правило приоритета: до прохождения приёмки Canvas не начинать новые большие ветки Spreadsheet/Relations/File Import. Уже существующие возможности сохраняются; исправление потери данных, регрессий, уязвимостей или проблем запуска допустимо на любом этапе.

## Этап 1. Canvas как законченный продукт

### 1.1 Инструменты, ввод и навигация (P0)

- [ ] Чёткая модель инструментов: Select / Hand / Pen / Eraser / Shape / Text / Connector. Переключение никогда не блокируется активным инструментом. *(Первый проход Select/Hand/Pen/Eraser выполнен, нужны ручные UX-тесты.)*
- [ ] Согласованное поведение мыши, колеса, тачпада и модификаторов; zoom к курсору; плавное panning без рывков.
- [ ] Двойной клик для редактирования текста, Esc для выхода; предсказуемое поведение selection при редактировании и панорамировании.
- [ ] Единая политика hotkeys: V, H/Space, Delete, Ctrl+C/V/D, Ctrl+Z/Y, Ctrl+A, +/- zoom. *(Первый проход реализован; требуется регрессионная проверка ввода и модальных окон.)*
- [ ] Fit-to-content, reset zoom, масштаб в процентах и мини-карта; выбор удобного масштаба при открытии.
- [ ] Empty state и доступная подсказка по управлению.

### 1.2 Выделение и геометрия (P0)

- [ ] Marquee / multi-selection (Shift); перемещение группы; resize без скачков и с сохранением пропорций.
- [ ] Smart guides: align к краям/центрам, одинаковые отступы, snap-to-grid с временным отключением.
- [ ] Rotate с предсказуемой точкой вращения и handles; корректные размеры текста и фигур.
- [ ] Layer ordering: bring forward/backward, send to front/back; понятная панель слоёв/объектов.
- [ ] Copy/paste и duplicate объектов **вместе с корректными внутренними связями**; удаление без осиротевших edges.
- [ ] Контекстная панель и меню по правому клику с одинаковой семантикой.

### 1.3 Группы, Frames и библиотеки фигур (P1)

- [ ] Настоящая модель Group / Ungroup / Frame; перемещение, resize и удаление группы без случайного захвата соседних элементов.
- [ ] Прикрепление/открепление объектов к Frame, вложенные Frames и прозрачные правила координат.
- [ ] Текст и стикеры: inline-редактор, перенос, оформление, Auto-size; фигуры с простым стилем, fill/stroke и opacity.
- [ ] Коннекторы с корректными якорями, стрелками, изгибами и поведением при перемещении узлов.
- [ ] Палитра, фигуры, повторное использование стилей, properties inspector.

### 1.4 Рисование, история и совместная работа (P1)

- [ ] Сглаженная кисть, предсказуемая толщина, быстрый выход из Pen/Eraser.
- [ ] Выделение, перемещение и удаление отдельных strokes; ластик работает по линии, а не случайно удаляет посторонние объекты.
- [ ] Undo/Redo для всех canvas-операций, включая resize/group/style/freehand; понятные границы транзакций.
- [ ] Realtime без потери объектов, с сохранением позиции, текста и порядка слоёв после перезагрузки.
- [ ] Права Viewer/Commenter реально блокируют запись, но не блокируют навигацию.
- [ ] Минимальная проверка производительности на досках с сотнями объектов; отсутствие заметных рывков и зависаний при навигации.

### 1.5 Согласованность интерфейса и контроль качества (P0/P1)

- [ ] Общие размеры и стиль кнопок, меню, всплывающих панелей, Inspector и toolbar.
- [ ] Состояния loading / error / reconnect / read-only не вводят пользователя в заблуждение.
- [ ] Регрессионные тесты инструментов/трансформаций/undo; E2E smoke test основных canvas-сценариев.
- [ ] Руководство пользователя по управлению Canvas и короткий demo board.

**Приёмка этапа 1.** Пользователь может на пустой доске создать инфраструктурную схему не менее чем из 100 объектов, сгруппировать и выровнять элементы, подписать, соединить, нарисовать комментарии, перемещать/редактировать, применять Undo/Redo, перезагрузить страницу и продолжить без потери данных. Это должно работать без Dataset и без обращения к специалисту для базовых действий. Проверяем мышь, тачпад и два параллельных подключения. Цель — плавное взаимодействие, а не формальное количество кнопок.

### Ближайшие три итерации Canvas

1. **Инструменты и навигация:** аудит pointer/keyboard handlers и overlay, фиксы Pen/Eraser/Select/Hand, panning/zoom, горячие клавиши и базовые E2E сценарии.
2. **Трансформация и выделение:** selection, resizing/rotation, smart guides, контекстные операции, копирование, порядок слоёв, согласованная история.
3. **Группы и эстетика:** настоящие Frame/Group, вложенность и закрепление объектов, polished Text/Sticky/Shape, инспектор и плавность на больших Board.

Каждую итерацию завершаем зелёным CI и **ручным сценарием приёмки в браузере**; успешная компиляция не заменяет проверку UX.

## Этап 2. Spreadsheet

**Цель:** таблица на Canvas работает как удобный компактный вид, а полный Dataset — как самостоятельный spreadsheet.

- Диапазоны, ввод, копирование/перемещение, вставка и удаление строк/колонок, reorder, resize, freeze panes.
- Формулы и типы данных, ссылки между ячейками, форматирование, условное форматирование, фильтры и сортировка.
- Доступность с клавиатуры, большие наборы данных, виртуализация сетки и отзывчивое редактирование.
- Настоящие table views, а не тысячи отдельных React Flow node для каждой ячейки.
- Realtime, права, безопасное сохранение и Undo/Redo данных.

**Приёмка:** импортированные или созданные вручную данные можно удобно редактировать и анализировать без повседневного возврата в Excel; встраивание одной таблицы на несколько Board не дублирует Dataset.

## Этап 3. Объекты и связи

- Привязка Dataset / Row / Column / Cell / Relation к объектам и шаблонам.
- Интуитивный binding UI: найти данные, выбрать строку/поле, preview, привязать и перейти к источнику.
- ER/FK/REF/DEP и визуальные связи; редактор кардинальностей и ограничения целостности.
- Умные инфраструктурные объекты, поля на иконках, шаблоны и повторное использование.
- Навигация через связи, представления одной записи на нескольких Board, корректные updates.

**Приёмка:** изменение IP/hostname сервера в Dataset отражается во всех связанных визуальных представлениях, а переходы и связи воспроизводимы и не требуют копирования данных.

## Этап 4. Файлы и дополнительные возможности

- Drag-and-drop с превью и валидацией: CSV, XLSX, SVG, изображения и поддерживаемые схемы.
- Импорт и экспорт таблиц и досок, форматирование и round-trip тесты.
- Файловое хранилище/права/лимиты, библиотеки SVG и шаблонов, версии/backup.
- Интеграции и дополнительные возможности администратора.

**Приёмка:** пользователь может загрузить файл, увидеть результат до подтверждения, безопасно отменить операцию и выгрузить его содержимое/схему без тихой потери данных.

## Общие инженерные принципы

- Релиз каждого этапа включает стабильное поведение, UI, тесты и документацию.
- Данные пользователя важнее скорости добавления функций: никаких destructive-миграций и скрытого изменения типов/связей.
- Один Dataset — один источник данных. Canvas/node/view и проекции PostgreSQL не должны конфликтовать друг с другом.
- Новая функция не считается готовой только из-за зелёного typecheck: нужен рабочий сценарий в браузере.
- Поддерживать текущие MVP-функции следующих этапов без масштабного расширения, пока не принят Canvas.

### Уточнение текущего прохода Canvas

Исправлена синхронизация геометрии во время локального drag/resize: входящие изменения сохраняют активный предпросмотр и применяют новые данные объектов. Frame перемещает содержимое локально и фиксирует результат в конце жеста. Последовательные перемещения разделены в Undo/Redo; удалённые другим участником объекты не восстанавливаются при завершении перетаскивания. Запись координат сохраняет актуальные текст, оформление и привязки из общего документа.

Автоматические проверки включают сохранение предпросмотра при входящих правках, удаление объекта, геометрию и границы истории Frame. Ручная проверка мышью/тачпадом и двумя браузерными подключениями **остаётся обязательной и пока не выполнена**: браузер текущего окружения не имеет доступа к локальному серверу, установка локального Chromium не удалась. Пункты приёмки этапа 1 остаются открытыми.

### Выделение, выравнивание и слои — следующий проход

В панель выделения добавлены меню **«Выровнять»** и **«Слои»**. Два и более объекта можно выровнять по краям или центрам, три и более — распределить с равными промежутками между краями (крайние объекты остаются на месте). Размеры берутся из измеренной геометрии, затем из явно заданных размеров. Frame переносит невыделенное содержимое вместе с собой по той же пространственной модели, что используется при перетаскивании; настоящие Group и вложенные Frame остаются отдельной задачей.

Порядок слоёв поддерживает передний/задний план и перемещение на один слой, сохраняя взаимный порядок выбранных объектов. Горячие клавиши: `Ctrl+]` / `Ctrl+[` и `Ctrl+Shift+]` / `Ctrl+Shift+[`. На macOS также поддерживается Command. Подъём объектов только из-за выделения отключён, чтобы отображался установленный порядок. Добавление к выделению явно привязано к Shift.

Каждая команда записывается одной транзакцией и отделена в Undo/Redo от предыдущего и следующего действия. Во время drag/resize команды недоступны; Viewer/Commenter не получают панель записи. Команды без изменений не создают запись истории. Автоматические тесты покрывают геометрию, размеры, разные ширины/высоты, неизменность исходных данных, Frame, порядок слоёв и историю. Ручная браузерная проверка по-прежнему не выполнена из-за описанного выше ограничения окружения; приёмка Canvas остаётся открытой.

### Контекстные действия и вставка в точку

Добавлено меню по правой кнопке на объекте, групповом выделении и пустом месте. При вызове на выбранном объекте сохраняется вся группа; на другом объекте выделяется только он. Меню использует существующие операции копирования, дублирования, Frame, удаления, выравнивания и слоёв, а также Undo/Redo и фокусировку. На пустом месте доступна вставка: верхний левый угол копируемого набора располагается в точке вызова, взаимные расстояния и внутренние связи сохраняются.

Меню управляется стрелками, Home/End, Enter и Escape; основные комбинации копирования, вставки, удаления, истории и слоёв работают и при открытом меню. Выход по Escape не сбрасывает выделение. Меню ограничено границами экрана, закрывается при клике снаружи, перемещении доски, прокрутке вне меню, изменении окна и потере фокуса. Для Viewer/Commenter доступны только копирование и навигация. В полях ввода и через Shift + правую кнопку сохраняется обычное меню браузера. В Select панорамирование правой кнопкой заменено контекстными действиями; средняя кнопка и Hand сохранены.

Выделены границы истории для вставки/дублирования, создания Frame и удаления. Начальные измерения DOM остаются локальными, чтобы не создавать лишний Undo и не рассылать служебную геометрию. При синхронизации локальные измерения сохраняются до явного изменения размеров.

Проверки: выбор группы при правом клике, координаты вставки, расположение у краёв экрана, доступность команд по правам и состоянию, сохранение измерений и отмена создания объекта. Ручная браузерная приёмка по-прежнему открыта из-за ограничения окружения. Сценарий для неё: два объекта + связь → копирование → правый клик на пустом месте → вставка → Undo/Redo; правый клик на выбранном и постороннем объекте; меню у нижнего/правого края; Esc; поля ввода; Viewer/Commenter.

### Свободное рисование и точный ластик

У кисти и ластика отключена привязка координат к сетке, независимо от настройки объектов. Перо обрабатывает объединённые события указателя, сохраняет конечную точку и поддерживает точку одиночным кликом. Частота предпросмотра ограничена animation frame; сохранение выполняется по завершении жеста, вне React state updater. Ширина штриха хранится в координатах доски и масштабируется вместе с ней.

Ластик удаляет **целые штрихи**, по которым прошёл указатель. Проверяется сглаженная SVG-кривая, включая промежутки между редкими исходными точками и траекторию быстрых движений ластика. Радиус ластика — 8 экранных пикселей, с учётом толщины линии; курсор показывает его размер. Геометрия штрихов кешируется на время жеста. До отпускания кнопки стирание является локальным предпросмотром, затем записывается одной транзакцией. Штрих, изменённый другим участником после попадания в предпросмотр, не удаляется.

Каждый завершённый жест пера или ластика — отдельное действие Undo/Redo. Esc, переключение инструмента, временная рука через Space, потеря фокуса, pointercancel и потеря pointer capture отменяют незавершённый жест. Запись допускается только для primary pointer и основной кнопки; Viewer/Commenter рисовать не могут. Перемещение viewport отменяет активный жест. Удаление узлов и работа с Dataset в этот проход не изменялись.

Тесты покрывают попадание между точками, сглаженную кривую, быстрое пересечение, непересекающиеся коллинеарные сегменты, толщину, zoom, точки и повторные сэмплы, конечную точку, транзакцию стирания и конкурентное изменение. Ручная браузерная приёмка пока остаётся открытой по описанному ограничению окружения. В неё входят рисование при включённой сетке, быстрый ластик на масштабах 15/100/250%, одиночная точка, отмена незавершённого жеста и восстановление нескольких стёртых штрихов одним Undo.
